# 演示视频脚本（demo-script.md）

> 原则：只演示当前真实可运行的功能；每一步都有可核验的产物；网络/模型失败有备用路径。
> 官方要求（来源：活动官网 oschina.net/os2026）：视频需展示**核心功能与使用流程**；未规定时长上限。
> **建议时长：6–8 分钟**，1080p，提前用纯净 profile 录制。

## 0. 录制前准备清单

- [ ] 干净的浏览器 profile（无残留 localStorage 图层），分辨率 1920×1080，缩放 100%。
- [ ] 服务启动（`start.bat` 默认以 `cn` 档启动；若需以 `competition` 档演示，请在终端执行 `set GISWTB_PROFILE=competition` 后再启动），确认底图正常加载。
- [ ] 模型服务配置好（设置 → AI 模型，DeepSeek/GLM 等兼容 OpenAI 接口的服务），并**预先跑通一次**确认可用。
- [ ] 演示数据：优先使用 `python scripts/prefetch_offline.py` 预热过的行政边界缓存（离线可复现）；本地准备一个小体积、可公开分发的 GeoJSON 作为备份输入。
- [ ] 录屏同时录旁白音轨或后期配音；准备失败预案：若模型服务断连，切换展示手动工具流程（第 3 节）。
- [ ] 检查桌面无个人隐私窗口/通知。

## 1. 时间分配（总 7 分钟）

| 时间 | 环节 | 展示重点 |
| --- | --- | --- |
| 0:00–0:40 | 开场 + 项目定位 | README 界面截图一闪而过；口播"自然语言 + 手动工具 + 2D/3D 一体" |
| 0:40–1:40 | 零配置手动工作流 | 不配 AI 也能用：导入 → 缓冲 → 导出 |
| 1:40–3:40 | AI Agent 任务编排 | 自然语言 → 工具调用 → 图层产物（核心环节，最长） |
| 3:40–5:00 | 离线分析与受控数据源策略 | 离线启动、底图与注记数据源、数据源准入档位口播 + 界面佐证 |
| 5:00–6:00 | 2D/3D 联动 + 产物核查 | 同一图层状态、执行台账、结果文件在磁盘 |
| 6:00–7:00 | 测试与工程化收尾 | 分层测试跑一遍 fast 模式 + 收尾口播 |

## 2. 分镜与旁白初稿

### 镜头 1（0:00–0:40）开场
- 画面：工作台首页面板（首次打开的指引 + 一键运行样例）。
- 旁白：「GIS WorkTable 是一个开源 GIS 工作台：数据接入、空间分析、2D/3D 展示和结果导出在同一个工作台完成。既可以手动操作，也可以用一句自然语言让 AI Agent 组合 GIS 工具。」

### 镜头 2（0:40–1:40）手动工作流（无需 API Key）
- 操作：导入 GeoJSON → 图层面板选中 → 打开手动空间分析 → 缓冲区 500 米 → 执行 → 查看结果图层与属性 → 导出 Shapefile。
- 旁白：「不配置任何模型 API，手动流程完整可用：导入数据、执行缓冲、检查结果属性，最后导出为兼容 QGIS 和 ArcGIS 的 Shapefile。注意右下角处理历史——每一步都可以重跑。」
- 必须拍到：结果图层出现在地图、处理历史面板、导出成功提示。

### 镜头 3（1:40–3:40）AI Agent（核心）
- 操作：AI 输入框输入「查询南京市鼓楼区的边界，并对它做 1 公里缓冲区」→ 展示工具调用过程（tool_start/tool_end 或工具面板显示的参数与结果）→ 结果图层挂载到地图 → 追问「刚才那个图层有多少要素」验证多轮实体继承。
- 旁白：「一个自然语言请求被拆解为两次真实工具调用：先用内置数据源拿到鼓楼区边界，再执行缓冲分析。注意左侧不是聊天回复，而是每次工具的真实参数与执行状态。多轮对话里，'它'能继承上一轮的图层实体。」
- 必须拍到：工具调用名称与参数、新图层在地图上出现、多轮继承问答。

### 镜头 4（3:40–5:00）离线分析与受控数据源策略
- 操作：断网（或口播说明）状态下刷新页面 → 前端 UI 正常加载（依赖随仓分发），本地分析流程仍可操作；切换底图展示国内白名单服务；口播部署档位：competition 档收紧外部在线下载并优先使用本地数据包。
- 旁白：「为适应不同的部署环境，前端依赖全部随仓库分发，断网也能正常启动并完成本地数据分析；底图与在线数据默认使用国内白名单服务（高德、天地图等），不依赖境外不可靠服务；competition 档进一步收紧外部在线下载，优先使用本地已校验数据包；白名单策略聚焦于应用层受控访问，空间分析成果需结合专业业务规范独立核验。」
- 必须拍到：断网后的页面加载、底图切换按钮、（可选）终端里 GISWTB_PROFILE 档位设置。

### 镜头 5（5:00–6:00）2D/3D 联动与产物核查
- 操作：切换 3D 视图 → 面要素拉伸展示；回到 2D；打开 `data/workspace.db` 对应的处理历史或 output 目录，展示真实生成的文件。
- 旁白：「2D 和 3D 共享同一份图层状态——在 3D 里做显隐，回到 2D 保持一致。每一次执行都有台账记录，产物文件真实落盘，'AI 说做了'可以被核实为'真的做了'。」
- 必须拍到：3D 拉伸效果、文件管理器里的真实产物文件。

### 镜头 6（6:00–7:00）工程化收尾
- 画面：终端运行 `python scripts/run_layered_tests.py --mode fast`，展示五层测试通过输出。
- 旁白：「项目建立了五层分层测试体系，从单元、Agent 决策到端到端全链路可回归。项目以 MIT 协议开源，欢迎试用与贡献。」

## 3. 失败预案

- **模型服务不可用**：跳过镜头 3 的 Agent 部分，完整展示镜头 2 手动流程 + 镜头 4/5，口播说明 AI 链路详见作品介绍文档。
- **在线数据失败**：改用离线预热的行政边界（prefetch_offline.py 已预热），口播说明这正是分层降级设计。
- **录制中 UI 卡顿**：提前重启服务清空 cache/ 中的会话残留。
