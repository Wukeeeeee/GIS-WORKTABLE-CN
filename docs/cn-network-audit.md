# CN 数据请求排查与调整

本次按 CN 仓库的国内数据源要求加固产品行为，默认画像为 `cn`。

## OSM 请求原因

- 原有画像仅从工具注册表移除了 OSM 边界和全球实体工具，通用网页抓取没有检查目标域名。
- CN 仍允许 OSM 路网下载；Python 沙箱允许导入 osmnx。
- 地图反向地理编码在高德不可用时自动回退 Nominatim。
- 卫星巡检默认尝试高德、Bing、Esri；影像报告还把高德错误标成 Bing。

## 已加固入口

- CN 工具注册表禁用 OSM 在线路网、全球实体、OSM 边界、Open-Meteo 天气和 USGS 地震；没有配置国内替代源的能力明确不可用。
- 网页抓取、固定服务请求、数据 Provider、GIS URL、云端文件读取经过 `network_policy.py`。HTTPS 和域名白名单在每次请求前检查，跳转逐跳检查，不把原查询参数和认证头传给跳转目标。
- CN 网页抓取使用受控 HTTP，避免浏览器子资源请求绕过检查。云端 GDAL 数据先经受控下载再本地读取。
- CN Python 拒绝 osmnx 和显式远程 URL；子进程增加 Python 网络审计钩子，阻止拼接 URL 后通过 Python socket 联网。
- 反向地理编码取消 CN 的 OSM 回退；卫星巡检仅使用高德；前端底图入口只接受高德、天地图及空白底图。
- 独立图表移除 jsDelivr/cdnjs 回退，使用仓库内置库。

## 界面

执行过程默认折叠，展示中文步骤和紧凑耗时，不再显示原始工具参数。会话忙提示及重试按钮收进同一张提示卡片。此改动改善展示，不改变服务端取消和会话锁的语义。

## 边界与部署要求

白名单维护在 `backend/services/network_policy.py`，不把任意 `.cn` 域名视为可信来源。`intl` 是现有显式配置的开放模式，CN 部署应保持 `GISWTB_PROFILE=cn` 或 `competition`。修改后需重启后端并刷新页面。

这是应用入口级网络策略，不是操作系统网络隔离。Python 审计钩子不能替代系统沙箱，原生扩展及其他未纳入该策略的模块仍需要独立审查。需要全进程禁止境外出站的部署应另配出站网关/防火墙，并覆盖模型供应商、代理、自定义服务、浏览器和原生库。

保留用户的模型凭据和代理配置；后续提交检查已增加国内模型目标白名单，并移除 CN 前端的境外模型预设。白名单不证明服务实际部署位置、数据授权、测绘资质、审图或个人信息处理合规。高德底图已接入 WGS-84→GCJ-02 显示投影，交互及导出保持 WGS-84；使用萧山机场缓存 AOI 验证了 2D 叠加与底图切换，并核对了 3D 投影计算，数据源边界精度仍需独立核验。当前加固不能作为“已全面通过中国法律合规审查”的结论。完整交付记录见 cn-demo-submission.md。
